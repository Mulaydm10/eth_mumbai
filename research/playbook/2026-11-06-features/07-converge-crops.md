## Entry 3 - Code findings: write/admission path (sure: high, read from source)
- main.ts:190 /api/ens-register is REQUIRED for a phone's readings to count (UI text: "Readings will not count until this phone has a name"). dashboard isLive (dashboard.ts:216) = ENS-resolved address == trigger $creator. So the README line "the onboarding gas faucet (/api/drip) is the one server we run" is FALSE: we also run /api/ens-register (committee), /api/ens-revoke (passcode), /api/time (clock reference for write timestamps). All admission/revocation goes through ONE hot key: api/_committee.ts "committee key is the team funder key (Vercel secret)" - same key funds Arkiv gas (drip.ts) and owns ENS roles. Compromise or loss = fake phones admitted or all admission stopped.
- /api/ens-register has NO auth and no per-person limit: anyone can create any site name (ensCreateSite if !siteExists) and register up to 5 phones with any labels/addresses (FIFO "site is full"). Consequences: (a) site squatting / DoS: a stranger can fill a society's site before its residents join (S/C); (b) Sybil: one person with 3 wallets registers 3 "phones" and meets k=3 if they can also stomp near them - quorum is cryptographic-identity, not independent-human. README S says "Quorum rejects a lone or spoofed phone": true for unregistered wallets, but registration itself is open. Severity MED (S), HIGH if pitched as tamper-proof evidence.
- Membership is evaluated against CURRENT ENS state (listSitePhones filters expiry > now; resolvePhones is "right now"). Phone names expire in 30 days (ens-register: expiryDays 30) and the committee can unregister. So a live viewer recomputing quorum for an event older than 30 days, or after revoke, drops those triggers: re-verification of old events depends on the committee having kept the phones registered. Sealed events (Swarm pack + packHash on Arkiv) mitigate only if the viewer/verify-event trusts the pack. README C says "nobody ... can edit, delete or withhold a confirmed event" and "Every viewer recomputes the quorum from public data": the second is true only for current membership; the committee (us) CAN retroactively un-count a past event by revoking a phone. MED-HIGH for the C claim as worded.
- /api/time: main.ts syncClock stamps event tMs (toWall includes refOffset) using our Vercel clock; time.ts comment "readers never depend on it" is TRUE for reading, but event times are anchored to a server we run unless the fetch fails (then silently falls back to phone clock). Neutral/LOW; state it.
- Privacy: phone publishes `ua: navigator.userAgent` (main.ts:317) in a public sensor entity plus exact times and a waveform excerpt (`wave`) per trigger: README P says "phone names pseudonymous, location only site" - omits UA string (fingerprinting). Phone key persists in localStorage tw.key across sites (same wallet for every site => cross-site linkability). Mic used only in sound.ts for sync timing; no audio leaves device (grep: no upload). "keys never leave the device": TRUE (key only in localStorage; /api/drip and /api/ens-register receive only the address; sealKey likewise). "No analytics or trackers": TRUE per source.
- Dashboard seal key (tw.sealkey) also gets gas via /api/drip: a read-only viewer without our backend can read but cannot seal (by design, comment dashboard.ts:34).

Unsealed events have no such freeze.
- swarm.ts: uploads via public gateway null stamp; comment admits retention "not documented"; pack hash on Arkiv lets anyone re-upload. Gateway = third party sees uploader IP and pack contents (public by design).

- F6 LOW (C): event times use /api/time reference when reachable (silent fallback to phone clock) so event timestamps are anchored to our server clock; time.ts comment is right that readers don't depend on it. State it.
- F7 LOW (C/O): the viewer file is a build artifact (apps/web/public/tremor-witness-viewer.html is byte-identical to dist-single; not git-tracked per `git ls-files`), served from our Vercel domain; "download it" depends on that domain until it is on Swarm/ENS contenthash (D3 idea F-10).
