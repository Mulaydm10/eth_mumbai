# D3 anon-rpc primary excerpts (fetched 2026-11-06 via curl; npm registry JSON)
URLs: https://ethereum.github.io/anon-rpc/ ; /wallets/ ; /networks/ ; https://registry.npmjs.org/@anon-rpc/browser-harness ; https://raw.githubusercontent.com/ethereum/anon-rpc/main/README.md

- Landing: "Just provide an Ethereum address at run-time and get an anonymized fetch function — anon-rpc plumbs the requests to a sandboxed worker running the network's hash-pinned client code." "An on-chain specifier contract pins the anon network's client code by keccak256. Any bytes matching the hash are acceptable, from anywhere." "The specifier owner can ship new worker versions on-chain — or renounce ownership and freeze the pinned hash forever."
- Wallets guide: `npm install @anon-rpc/browser-harness`; `new AnonRpcWorker({address, config, preExisting:{rpcProvider}})`; `await worker.fetch("https://rpc.example/", {method:"POST", body: JSON-RPC})`. "worker.fetch is this-bound — pass it as a free function to anything that accepts a custom fetch or transport (a viem custom transport, an ethers FetchRequest getUrl hook...)". => it proxies fetch to ARBITRARY https URLs (not only Ethereum RPC); one AnonRpcWorker per network, long-lived.
- Networks listed in guide: passthrough (NOT anonymised, demo of sandbox+hash pinning), tor-js (Tor in WASM, bootstrap delay, demo gateway "may disappear"), nym (mixnet WASM, bundle ~18 MB, few seconds bootstrap), nox ("Wraps each request in Sphinx packets routed through entry, mix and exit nodes, dialled over KPS. TLS to an https RPC runs inside the worker, so the exit node relays the request without reading it... Published on the Sepolia testnet: rpcProvider must answer for Sepolia"; specifier 0x35133267A8F7EC35046a83DCA0f4Ca8A6e1b7A9A). Mainnet specifiers: passthrough 0x4fd77be3..., tor 0x700dA319..., nym 0x3aCD9742....
- `anonOptions: { isolationKey: accountId }` "asks that calls under different keys not be linkable to one another — e.g. one key per account. Support varies".
- Trust: "You are trusting the on-chain hash — that is, whoever controls the specifier contract... Your bootstrap provider is trusted for one read... not anonymized". Worker "sees every request ... a malicious worker can observe, censor, or lie." Browser-only (null-origin iframe, WebRTC KPS).
- npm @anon-rpc/browser-harness 0.4.0, MIT, modified 2026-10-28; deps @anon-rpc/harness-core, @noble/hashes, @kpstreams/webrtc-client. Description: "loads a hash-pinned anon-client worker under null-origin iframe isolation and exposes an anonymized fetch (SPEC §3.1 conformance target)".
- Prize text (ethglobal-ef-crops.md): "Your app routes its RPC reads through Anon-RPC by default." Judging: "how much of the app's traffic goes through Anon-RPC (if an app)"; exclusions as intentional tradeoff OK if stated; ideas: "combine anon-rpc with a light client or proof verification".
